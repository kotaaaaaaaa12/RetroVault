Changelog

Changes to Retro Vault. These version numbers belong to this site, not EmulatorJS.

2.17.12026-10-31Latest

Safari 3DS shader-cache default

  • Default Safari 3DS shader caching to OFF on the pinned runtime and migrate its saved preference once. Hardware shaders and saves are preserved. The comparison does not establish a crash cause, long-term stability, or improved FPS.
2.17.02026-10-30

3DS startup and memory comparison tests

  • Added private 3DS comparisons with isolated temporary saves, startup stages, memory region samples, native core setting readback, observed outcomes, and retained results. This does not establish a cause or fix for the Safari reload.
2.16.02026-10-30

Reuse device ROM downloads and reduce diagnostic overhead

  • Completed Safari 3DS downloads now stay on this device and are reused when the server URL, ETag, size, and cached header agree. Device downloads lists stored copies and supports individual or bulk deletion while protecting files in use. Incomplete copies are not reused. Forced verbose startup logging is removed and production debug lines are counted without repeatedly rebuilding diagnostic logs. This does not establish or confirm a fix for an unrecorded browser-process crash.
2.15.02026-10-30

Prepare Safari 3DS ROMs in temporary device storage

  • Safari now downloads library 3DS ROMs into a temporary device file before mounting them. A progress panel shows downloaded bytes and supports cancellation. Playback reads the local copy without ROM network requests, while preserving verified header corrections and bounded memory reads. Normal closing removes the copy. Unavailable storage or insufficient quota stops preparation with an explanation.
2.14.12026-10-30

Handle optional wake-lock denial and identify ROM read failures

  • Rejected screen-awake requests are now recorded by operation without producing an unhandled player error. Other permission failures remain visible. ROM diagnostics distinguish HTTP failures, changed objects, invalid responses, network errors, and response, body, or main-thread wait timeouts, including the failing byte range. These records do not establish the cause of earlier stackless permission errors.
2.14.02026-10-30

Load verified plaintext 3DS content with stale encryption flags

  • The library range loader now checks the extended header, ExeFS superblock and files, and the RomFS superblock before correcting a stale no-crypto flag in bytes passed to the core. Stored ROMs remain unchanged. Failed or unsupported checks leave the flag untouched, and diagnostics record each check and any correction. This is not a full RomFS integrity check.
2.13.42026-10-30

Check the 3DS extended-header hash

  • Library ROM diagnostics compare the standard NCCH extended header with its stored SHA-256 digest using the existing range probe. Logs distinguish matches, mismatches, and checks that could not run. This checks only the extended header, not the entire ROM. Files and encryption flags are not changed.
2.13.32026-10-30

Record the 3DS ROM header flags

  • Library ROM diagnostics now record the loaded filename, NCSD/NCCH header metadata, the no-crypto flag, and the corresponding flag bytes delivered to the core. Inspection reuses the existing range probe without extra downloads or modifying the file. A header flag or loader classification alone does not independently verify payload decryption.
2.13.22026-10-30

Explain encrypted 3DS ROM failures

  • The pinned Azahar encrypted-content loader error now produces a translated notification. A later frontend start callback does not clear that error. Explicitly harmless core-option notices no longer occupy the retained issue list. ROM contents and encryption flags are not changed.
2.13.12026-10-30

Record native 3DS startup messages

  • 3DS diagnostics now capture bounded native core output, preserve startup issues, and record entry-point return values, WebGL context creation, and canvas dimensions. Production caching remains enabled. A frontend start notification or zero return code does not prove that the game loaded. This update gathers evidence for black-screen failures; Safari game startup is not yet verified.
2.13.02026-10-30

Storage usage by system

  • File storage now includes a doughnut chart and a capacity, share, and file-count list. Completed ROM uploads are grouped by system; thumbnails, BIOS, patches, and unclassified ROMs each have a separate category. Shared files are counted once, and uploads in progress are excluded. The view updates after library/file changes and language switches.
2.12.42026-10-30

Use block reads for native 3DS downloads

  • Fixed an integration error where the native uppercase ROM download type bypassed block reads and used the full-file downloader. Routing now matches the exact ROM source; unsupported adapters stop that source without falling back. Loading diagnostics use the same source match. The pinned native pipeline and Azahar file system passed range-only reads beyond 2 GiB with a synthetic file; Safari game startup remains unverified.
2.12.32026-10-30

Release language selector focus

  • All language selectors now share focus cleanup after a selection, including the changelog and core comparison pages. Native picker dismissal is checked again without moving focus away from another control.
2.12.22026-10-30

DS touch uses the displayed position

  • The pinned melonDS runtime now defaults to Touch mode for direct finger taps and mouse clicks. Existing Mouse preferences migrate once; later manual choices are respected. Save data, controls, and cheats are retained. Diagnostics include the selected touch mode. Safari game-level verification is still required.
2.12.12026-10-30

DS screen touch routing

  • Restored DS canvas hit testing on the pinned frontend while allowing touches through empty virtual-gamepad areas. Actual buttons and the D-pad remain interactive. Diagnostics count canvas touch/pointer events without recording coordinates. Safari game-level stylus behavior still requires device verification.
2.12.02026-10-30

One set of nine save slots

  • The save panel, native quick-save/load controls, and native state toolbar share nine durable slots. Keys 1 and 2 save and load the selected slot; key 3 cycles through slots 1–9. Existing Retro Vault slots 1–3 remain available without conversion. Browser restarts preserve completed saves; failed writes retain the prior durable state.
2.11.02026-10-30

Read library 3DS ROMs in blocks

  • Library 3DS ROMs use verified 256 KiB HTTP range reads and an 8 MiB cache on the pinned Azahar runtime. Full-file responses, changed objects, and invalid ranges stop startup instead of falling back to a full download. Diagnostic stages distinguish core initialization from ROM loading. Safari game startup remains unverified.
2.10.12026-10-30

Readable site version numbers

  • Site releases start at 1.0.0. Features increment the minor number and fixes increment the patch; the Workers architecture migration starts 2.0.0. Earlier entries retain their original dates. Diagnostics, package metadata, and asset cache versions use the same site version.
2.10.02026-10-30

Bounded local 3DS reads

  • Large local 3DS files use a read-only file adapter with 1 MiB blocks and an 8 MiB cache on the pinned Azahar runtime. A binary-read compatibility check must pass first; unsupported environments stop instead of retrying a full-file allocation. Game startup on the reporting Safari device remains unverified.
2.9.02026-10-30

Conservative local 3DS padding preparation

  • Retro Vault verifies standard CARD1 partition boundaries and scans trailing padding in small chunks before omitting it for startup. Original files and save identities remain unchanged. CARD2 and unverified layouts are not trimmed. This is a Retro Vault feature, and does not guarantee large-ROM startup.
2.8.12026-10-29

Direct local ROM loading and request diagnostics

  • Local ROMs are passed as named File objects, matching the official demo and avoiding a blob URL fetch. Local save identities remain unchanged.
  • Diagnostics include local ROM size and read failures, plus a bounded list of requested resources and HTTP failures. The supplied Safari 3DS log did not identify the failing resource; this change does not establish that its startup failure is resolved.
2.8.02026-10-29

File storage categories

  • File storage is grouped into expandable ROM, thumbnail, BIOS, and patch categories. Headings show file counts and completed sizes. Open categories stay open after updates and language changes.
2.7.02026-10-29

Upload progress and corner notifications

  • Errors and completion messages appear as dismissible notifications at the bottom right. Player errors are shown once without adding bars above or below the game.
  • A fixed upload panel shows the current file, queue position, bytes, and progress while each part is sent. Failed transfers, retries, and cancellation keep their existing behavior.
2.6.12026-10-29

Consistent save panel typography

  • The library, management, changelog, and save panel use one shared pixel logo style. Save panel fonts are protected from the emulator's global font reset in both languages.
2.6.02026-10-29

Choose the game order

  • Use Up and Down in management to change the library order. Each change saves immediately and is used by the public library, search results, and system filters. New games append at the end.
  • Reordering preserves game IDs, saves, and unsaved editor content. Stale ordering changes are rejected, and JSON export/import retains the array order.
2.5.02026-10-28

Unified Vault design and bilingual game titles

  • Library management and device saves share the Vault colors, pixel logo, and panel styling. Search, language, and local ROM controls sit in the library header.
  • English and Japanese titles can be entered separately. A single title is used in both languages, search matches both, and native save identifiers remain fixed.
  • System filters show game counts. The list summary includes the combined ROM size of the games currently shown. Updated the footer to Powered by EmulatorJS while retaining the Japanese separator.
2.4.12026-10-28

Mobile startup audio compatibility and input diagnostics

  • Replaced the prerelease mobile Safari audio check that assumes an OpenAL context exists. Existing suspended audio can resume during a trusted tap without consuming the control input or opening an audio-wait popup.
  • Diagnostics identify failed audio, gamepad, fullscreen, and pointer-lock operations and record input-event counts. Input contents are not recorded. Permission errors are retained; the specific cause of an earlier unnamed denial remains unconfirmed.
2.4.02026-10-28

Select the system automatically when choosing a ROM

  • ROM uploads and uploaded-file selections detect the system from known extensions, including when editing an existing game. Switching systems selects the default core; choosing another ROM for the same system preserves a custom core.
  • Ambiguous formats remain manually configurable. A failed or cancelled upload restores the previous system if no ROM completed.
2.3.02026-10-28

Multiple uploads and readable file sizes

  • ROM and thumbnail pickers accept multiple files. Uploads run sequentially with per-file results, progress, retries, and cancellation. Completed files remain available if another file fails.
  • Small file sizes use bytes or KiB instead of rounding to 0.0 MiB. Larger files use MiB or GiB.
2.2.02026-10-28

Open the library without signing in

  • The game library, player, and published game files are available without signing in. Only management and the NES comparison test require the administrator password.
  • Draft, trashed, and unused files remain restricted to management unless another published game uses them.
2.1.02026-10-28

Choose the login password in Cloudflare

  • Set ADMIN_PASSWORD as a Worker secret using your chosen password directly. No manual password hashing is required.
  • Password checks run in the Worker. Changing the password invalidates existing sessions.
2.0.02026-10-28

Workers deployment and private library management

  • Added password-protected game management with ROM and thumbnail uploads, system/core selection, draft publishing, JSON import/export, and trash.
  • Moved catalog data to D1 and files to private R2 storage. Wrangler prepares interface assets and deploys everything with one deploy command. ROM folders are excluded from static assets.
  • Moved the NES comparison test into management. The footer contains the changelog, EmulatorJS credit, and diagnostic download when available.
